`babel-plugin-saykit` is for builds that run Babel: Next.js, React Native, Expo, or your own setup. Not pinned to Babel? Use [`unplugin-saykit`](/integrations/vite).

## Install

```sh
pnpm add -D babel-plugin-saykit @saykit/config @saykit/format-po @saykit/transform-js @saykit/transform-jsx
```

## Use

### Next.js

```json title=".babelrc"
{
  "presets": ["next/babel"],
  "plugins": ["saykit"]
}
```

Adding a `.babelrc` switches Next.js from SWC to Babel. There is no SWC plugin, so this is how SayKit runs in Next.js. `next.config.mjs` needs no SayKit wrapper.

### Expo

```js title="babel.config.js"
module.exports = function (api) {
  api.cache(true);
  return {
    presets: ['babel-preset-expo'],
    plugins: ['saykit'],
  };
};
```

Bare React Native is the same with `module:metro-react-native-babel-preset`. `metro.config.js` needs no SayKit wrapper.

### Plain Babel

```js title="babel.config.js"
export default {
  plugins: ['saykit'],
};
```

## What it does

The plugin rewrites macros to `say.call(...)` in every source file outside `node_modules`. That is all. Catalogues are compiled by [`saykit compile`](/reference/cli#saykit-compile) into ordinary `{locale}.js` modules, which Next.js and Metro load and hot-reload like any other module.

<Callout type="info">
  Run `saykit compile` before anything that imports those modules, usually as `predev` and
  `prebuild` scripts. Keep `saykit extract --watch` running in development to recompile when a
  translation changes.
</Callout>

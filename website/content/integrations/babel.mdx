`babel-plugin-saykit` is the Babel counterpart to [`unplugin-saykit`](/integrations/vite). Use it when your build runs Babel directly: Next.js (via `.babelrc`), React Native, Expo, Metro, or your own Babel setup.

## Install

```sh
pnpm add -D babel-plugin-saykit
```

And the supporting packages:

```sh
pnpm add -D @saykit/config @saykit/format-po @saykit/transform-js @saykit/transform-jsx
```

## Use

### Next.js

```json title=".babelrc"
{
  "presets": ["next/babel"],
  "plugins": ["saykit"]
}
```

Adding a `.babelrc` switches Next.js from SWC to Babel for compilation. SayKit doesn't have a SWC plugin, so this is the supported way to use SayKit with Next.js today.

Nothing else to register: `next.config.mjs` needs no SayKit wrapper.

### Generic Babel

```js title="babel.config.js"
export default {
  plugins: ['saykit'],
};
```

Or with an explicit import:

```js
export default {
  plugins: ['babel-plugin-saykit'],
};
```

### React Native / Metro

React Native uses Babel via Metro. Add the plugin to your Babel config:

```js title="babel.config.js"
module.exports = {
  presets: ['module:metro-react-native-babel-preset'],
  plugins: ['saykit'],
};
```

### Expo

Expo uses `babel-preset-expo`. Add the plugin alongside:

```js title="babel.config.js"
module.exports = function (api) {
  api.cache(true);
  return {
    presets: ['babel-preset-expo'],
    plugins: ['saykit'],
  };
};
```

`metro.config.js` needs no SayKit wrapper either.

## What it does

The Babel plugin runs the matching SayKit transformer over every non-`node_modules` source file, rewriting macros to `say.call(...)` invocations. That is the whole of its job.

Catalogues are not its business. [`saykit compile`](/reference/cli#saykit-compile) turns each one into an ordinary `{locale}.js` module, walking the locale's [fallback chain](/core-concepts/configuration#fallback-locales) so untranslated keys fall back to the source string. Your app imports that module, and every bundler already knows how to load, watch and hot-update a module.

The result: no message parser at runtime, no SayKit extractor in the bundle, just small `say.call()` calls and one plain module per locale.

<Callout type="info">
  Run `saykit compile` before anything that reads those modules. A `predev` and `prebuild` script
  is the usual way; `saykit extract` also compiles as its last step, and `saykit extract --watch`
  recompiles when a translation changes.
</Callout>

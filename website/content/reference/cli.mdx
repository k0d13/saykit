The `saykit` CLI ships with `@saykit/config`. It has three commands: `extract`, `compile` and `clean`.

```sh
saykit help [command]
```

Every command takes these flags:

## `saykit extract`

Extracts messages from each bucket's `include` files, writes the **source** locale's catalogue, then compiles every locale as [`compile`](#saykit-compile) does. Other locales are never edited; one with no file yet is created empty so a TMS can register it.

```sh
saykit extract
saykit extract --watch
```

<TypeTable
  type={{
    '--watch, -w': {
      description:
        'Keep running: re-extract when a source file changes, and recompile when a catalogue does.',
      type: 'boolean',
      default: 'false',
    },
  }}
/>

Messages with the same text and context are merged into one entry with every reference. Ids are hashed for messages without a custom one.

## `saykit compile`

Compiles each locale's catalogue into the `{locale}.js` module your app imports, beside the catalogue. Run it on its own when there is nothing to extract: a build from a fresh clone, or after pulling translations from a TMS.

```sh
saykit compile
```

For each locale it reads the catalogue and its [fallback chain](/core-concepts/configuration#fallback-locales), compiles each ICU message to a [`Message`](/reference/api/saykit#message) with every style resolved to `Intl` options, and writes `{locale}.js` and `{locale}.d.ts`:

```js title="src/locales/fr.js"
// Generated by saykit. Do not edit.
export default {
  // {count, plural, one {# article} other {# articles}}
  c4Ef_2: [3, '_count', { one: [[6], ' article'], other: [[6], ' articles'] }],
};
```

Nothing parses a message at runtime, and since the module is data, a server can hand it to a client like any other JSON.

<Callout type="info">
  Keep the `.js` out of version control. Commit the `.d.ts`: it never changes, and it lets `tsc`
  pass on a fresh clone.
</Callout>

## `saykit clean`

Removes dead entries from every non-source locale. It only subtracts:

- **drops** keys no longer in the source catalogue,
- **drops** empty translations, which fall back anyway,
- **leaves** everything else byte-for-byte.

Keys missing from a locale are left for your TMS to add. `clean` is optional; if your TMS prunes orphans you may never need it.

```sh
saykit clean
```

## Configuration discovery

The CLI looks for `saykit.config.{ts,mts,cts,js,mjs,cjs}` from the working directory upwards; the first match wins. See [Configuration → Loading](/core-concepts/configuration#loading).

## Scripts

The compiled modules are not committed, so anything that imports them should compile first:

```json title="package.json"
{
  "scripts": {
    "extract": "saykit extract",
    "predev": "saykit compile",
    "prebuild": "saykit compile",
    "pretest": "saykit compile"
  }
}
```

In CI, check that extraction was run:

```yaml
- run: pnpm saykit extract
- run: git diff --exit-code -- 'src/locales/*.po'
```

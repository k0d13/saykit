`@saykit/config` exports `defineConfig`, `loadConfig`, `messageKey` and the config types. The `saykit` CLI and the build plugins are built on them.

```ts
import { defineConfig, loadConfig, messageKey } from '@saykit/config';
import type { ConfigInput, SayKitConfig, Bucket, Formatter, Transformer, Message } from '@saykit/config';
```

Most application code only uses `defineConfig` and the types. `loadConfig` and `messageKey` are for plugin, formatter and transformer authors.

## `defineConfig(config)`

Type a SayKit configuration. It returns the config unchanged and does not validate it; that happens in [`loadConfig`](#loadconfigoptions).

```ts title="saykit.config.ts"
import { defineConfig } from '@saykit/config';
import po from '@saykit/format-po';
import js from '@saykit/transform-js';

export default defineConfig({
  locales: ['en', 'fr'],
  buckets: [
    {
      include: ['src/**/*.ts'],
      output: 'src/locales/{locale}.{extension}',
      formatter: po(),
      transformer: js(),
    },
  ],
});
```

## `loadConfig(options?)`

Search up from `options.cwd` (default `process.cwd()`) for `saykit.config.{ts,mts,cts,js,mjs,cjs}`, load it, validate it and return a `SayKitConfig`. Throws a readable error if the file is missing or invalid. Configs exported without `defineConfig` are accepted.

```ts
const config = loadConfig();
config.compile();
```

The config is loaded from where it sits, so its relative imports and `import.meta.dirname` resolve against its own directory. Reading TypeScript requires Node 22.18+ or a runtime that loads it itself (Bun, Deno, tsx). The `saykit` CLI, `unplugin-saykit` and `babel-plugin-saykit` all load it this way.

### `SayKitConfig`

- `root`, the config file's folder. Relative paths in the config (`output`, `include`, `exclude`) resolve against it, not the working directory
- `file`, `locales`, `sourceLocale` (the first locale)
- `buckets`, the resolved buckets: `include`, `exclude`, `output`, `formatter`, `transformer` (merged) and `messages`, plus `includes(file)`, `cataloguePath(locale)` and `isCatalogue(path)`
- `compile()`, compiles every bucket and locale into `{locale}.js` and `{locale}.d.ts`, following the [fallback chain](/core-concepts/configuration#fallback-locales), skipping writes that would not change a file
- `fileChanged(path)`, recompiles the buckets that read a changed catalogue, or returns `[]` for any other file
- `watch()`, recompiles whenever a catalogue changes and returns a function that stops watching
- `extract({ watch? })`, extracts from source, writes the source locale, adds missing locales and compiles; with `watch`, keeps going
- `clean()`, prunes untranslated and stale entries from the other locales, as `saykit clean` does
- `transform(code, file)`, runs the matching bucket's transformer, or returns `undefined` if no bucket includes the file. Accepts absolute or root-relative paths and ignores a `?query`

`compile`, `fileChanged` and `watch` return `CompiledModule`s: `{ bucket, locale, path, sources, count, written }`. `sources` lists the catalogue files read, most specific first, for a bundler's `addWatchFile`. Library calls only log errors; the CLI adds its own progress output.

## `messageKey(message)`

The key SayKit stores a message under: its `id` if it has one, otherwise the 6-character hash of `message` and `context`. Formatters and transformers should key with it so catalogues match what the runtime looks up.

```ts
messageKey({ message: 'Hello', context: 'greeting' });
```

## `@saykit/config/messages`

The message types transformers work with (different from the public catalogue `Message` shape), plus helpers:

```ts
import {
  compileMessage,
  assignSequenceIdentifiers,
  CompositeMessage,
  LiteralMessage,
  ArgumentMessage,
  ChoiceMessage,
  ElementMessage,
} from '@saykit/config/messages';
```

- `compileMessage(icu)`, compiles one ICU message to the runtime's [`Message`](/reference/api/saykit#message)
- `assignSequenceIdentifiers(message, { current: 0 })`, numbers positional placeholders depth-first

These let custom transformers produce the same placeholder shape the built-in transformers do.

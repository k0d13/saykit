SayKit is split into a small core runtime and a set of optional packages for configuration, formatters, transformers, and framework integrations. Pick the pieces you need.

## What to install

Every SayKit project needs the same set of pieces:

| Package                      | Why                                                                |
| ---------------------------- | ------------------------------------------------------------------ |
| `saykit`                     | The core runtime: catalogues, views, stores and ICU formatting     |
| `@saykit/config`             | The config schema (`defineConfig`) and the `saykit` CLI            |
| One **formatter**            | Reads and writes your translation files (e.g. `@saykit/format-po`) |
| One or more **transformers** | Extracts and rewrites macros from your source files                |
| One **build-tool plugin**    | Wires the transformer into your bundler                            |

<Callout type="info">
  The build-tool plugin and the transformers do different jobs: the **transformer** knows how to
  parse and rewrite `.ts`/`.tsx` source, the **plugin** knows how to hook your bundler. You usually
  install both.
</Callout>

## Peer dependencies

A few packages have peer requirements worth knowing about:

- `@saykit/react` peers `react` and `saykit`. The package uses the `react-server` export condition for server rendering, so React 18+ is required and React 19+ is recommended.
- `@saykit/carbon` peers `@buape/carbon` and `saykit`.
- `babel-plugin-saykit` expects `@babel/core` (you almost certainly already have it).

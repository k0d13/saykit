# Welcome to SayKit

SayKit is a framework-agnostic internationalisation toolkit built around **compile-time message extraction**, **typed configuration**, and **small runtime primitives**.

You author messages inline with tagged templates or JSX. The `saykit` CLI extracts them to translation files and compiles each locale into a module of plain data, and a build plugin rewrites your source to small runtime calls. At runtime a view formats those messages with `Intl`: plurals, ordinals, select, numbers and dates, with nothing left to parse.

<Callout type="warn">
  SayKit is in active development (pre-1.0). Public APIs may change before the stable 1.0 release.
</Callout>

## How it works

SayKit wires up like this:

1. You **author** messages with `` say`...` `` or `<Say>...</Say>` in source files.
2. The `saykit` CLI **extracts** them into per-locale files (`src/locales/en.po`, `fr.po`, &hellip;).
3. Translators (or you) fill in the translations in those files.
4. The CLI **compiles** each locale into a module (`src/locales/fr.js`) that your app imports like any other.
5. At build time a SayKit plugin **transforms** your source: macros become small `say.call(...)` calls.
6. At runtime, `catalogue.locale(...)` returns the locale-bound `View` that **formats** messages on demand.

There's no SaaS, no proxy, no extra service. Translation files live in your repo, next to the code they describe.

A **formatter** reads and writes one catalogue format. The CLI uses it to write the source catalogue on `extract`, and to read every catalogue on `compile`; your app never sees it.

```ts title="saykit.config.ts"
import po from '@saykit/format-po';

buckets: [
  {
    // ...
    formatter: po(),
  },
];
```

**PO** (Gettext) is the default, and the format most translation tools already speak. **JSON** ([`@saykit/format-json`](https://github.com/k0d13/saykit/tree/main/packages/format-json)) is there for projects that want plain JSON, ARB or WebExtension files.

## PO

PO files look like this:

```po title="src/locales/fr.po"
msgid ""
msgstr ""
"Project-Id-Version: \n"
"Language: fr\n"
"Content-Type: text/plain; charset=UTF-8\n"
"X-Generator: saykit\n"

#. Translator comment from the source
#: src/app/page.tsx:14
#: src/app/inbox.tsx:8
msgid "Hello, {name}!"
msgstr "Bonjour, {name} !"

msgid "Inbox"
msgctxt "noun"
msgstr "Boîte de réception"
```

Each entry has:

- `msgid`, the source string (or ICU MessageFormat for plural/select)
- `msgstr`, the translation (empty for new entries)
- `msgctxt`, the descriptor's context, if any
- `#.`, translator comments (from `// TRANSLATORS:` lines)
- `#:`, source references (file:line)
- `#. id:xxxx`, SayKit's stable id (for messages without a custom id)

PO is readable, diffs line by line, and is understood natively by POEdit, Crowdin, Lokalise, Weblate and Transifex.

## JSON

`@saykit/format-json` writes one JSON file per locale, keyed by message id (the content hash when there is no custom id), with the translation as the value.

```ts title="saykit.config.ts"
import json from '@saykit/format-json';

buckets: [
  {
    // ...
    formatter: json(),
  },
];
```

```json title="src/locales/fr.json"
{
  "greeting": "Bonjour, {name} !",
  "inbox": "Boîte de réception"
}
```

This plain layout is lean but drops comments, context, and source references, so give your messages explicit ids to get stable, readable keys.

### Dialects

To keep the metadata a plain `{ key: value }` map can't hold, pass `dialect` to switch to a richer but still standard JSON layout.

<TypeTable
  type={{
    dialect: {
      description:
        "`'arb'` for Application Resource Bundle (Flutter/Dart `intl`), where strings stay flat and each key's metadata lives in a sibling `@key` object; `'webextension'` for the Chrome `messages.json` shape, where each key maps to a `{ message, description }` object. Omit for a plain flat catalogue.",
      type: "'arb' | 'webextension'",
    },
  }}
/>

```ts
formatter: json({ dialect: 'arb' });
```

```json title="src/locales/fr.json (ARB)"
{
  "@@locale": "fr",
  "greeting": "Bonjour, {name} !",
  "@greeting": {
    "description": "A friendly hello",
    "x-saykit-context": "formal",
    "x-saykit-references": ["src/app/page.tsx:14"]
  }
}
```

Both formats carry translator comments in their native `description` field. Context and source references have no standard slot, so SayKit round-trips them through `x-saykit-context` / `x-saykit-references` extension fields, and other tooling reads the `description` and safely ignores the rest.

### References

As with PO, you can trim or drop the source references a dialect writes. Neither option affects the plain layout, which carries no metadata to begin with.

<TypeTable
  type={{
    includeReferences: {
      description: 'Include source references (`x-saykit-references`) in the output.',
      type: 'boolean',
      default: 'true',
    },
    includeLineNumbers: {
      description:
        'Include line numbers in source references. Set to false for cleaner diffs when only references churn.',
      type: 'boolean',
      default: 'true',
    },
  }}
/>

```ts
formatter: json({ dialect: 'arb', includeLineNumbers: false });
```

## Other formats

For YAML, XLIFF or anything else, a `Formatter` is a plain object. Its extension cannot be `.js`, which is where the compiled module goes.

```ts
import type { Formatter } from '@saykit/config';

const json: Formatter = {
  extension: '.json',
  parse(content) {
    /* return Message[] */
  },
  stringify(messages, { locale, existingContent }) {
    /* return string */
  },
};
```

See the [custom formatter guide](/guides/custom-formatter) for a complete walkthrough.

## The `Message` shape

Formatters work with this shape, exported from `@saykit/config` (not the runtime's compiled `Message`):

<TypeTable
  type={{
    message: {
      description: 'The ICU MessageFormat string for the entry.',
      type: 'string',
      required: true,
    },
    translation: {
      description: 'The translation, if any. Empty string or undefined for new entries.',
      type: 'string',
    },
    id: {
      description:
        'Custom id if provided in a descriptor; otherwise undefined (hashed at write time).',
      type: 'string',
    },
    context: {
      description: 'The descriptor context, if any.',
      type: 'string',
    },
    comments: {
      description: 'Translator comments, from `// TRANSLATORS:` lines or your own.',
      type: 'string[]',
    },
    references: {
      description: 'Source locations as `file:line` strings.',
      type: 'string[]',
    },
  }}
/>

`stringify` receives an array of these and `parse` returns one.
